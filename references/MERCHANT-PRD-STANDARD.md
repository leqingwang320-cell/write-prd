# 商家端 PRD 专项规范

> 来源：Cooper《商家端产品需求文档规范_2026年7月》（resourceId: `2208838836051`）。本文件是公司内部 PRD 基础规范，每次使用本 Skill 时必须读取；通用入口门槛、模板与质量规则同时生效。任何冲突均不得降低通用安全、隐私、异常恢复和验收要求。

## 适用方式

本规范是强制基础规范。需求面向外卖平台商家端时，核心用户应是商家角色，如老板、店长、店员；前线运营、客服、产运、BD 等内部角色不能被默认写成商家端产品的核心用户。

如果需求同时服务商家与内部角色，必须分别说明各角色价值，并明确第一版核心用户。不能把内部效率或战略支持包装成商家价值。

如果具体需求不属于商家端，仍须执行本规范的需求真实性、价值归属、时机判断、WHY / WHAT / HOW、直接收益、Before / After 和内审要求；其中“商家”按真实核心用户替换，不得强行制造商家价值或商家渠道。

## 写作前：先判断是否在做对的事

### 1. 收集信息

- 需求从哪里来、为何提出、为何现在提出。
- 对商家的直接价值是什么。

### 2. 挖掘本质

- 区分对方给出的是解决方案还是商家问题。
- 记录表面现象、商家原声、当前做法与替代解法。
- 判断实际价值归属：商家、外部用户、内部运营或战略支持。
- 判断影响面：个别商家定制、特定分群还是广泛商户收益。
- 判断价值周期：长期能力还是项目期内的短期收益。
- 评估投入是否值得，包括 ROI、成本与机会成本；没有数据时标为待验证，不编造结论。
- 判断当前时机、必须完成的程度和可以后置的范围。

### 3. 形成结论

写 PRD 前必须能明确：

1. 真正要解决的商家问题。
2. 采用的解决方案。
3. 一句话说明方案为何能解决该问题；无法说明时继续澄清。
4. 上线后创造的直接价值。
5. 合适的实施时机与阶段范围。

以上缺口按 `PRD-ENTRY-GATE.md` 处理，不因加载本规范而绕过入口门槛。

## PRD 内容覆盖：WHY / WHAT / HOW

### WHY：背景与来源

清楚描述需求背景、来源、提出原因、当前时机，以及方案诉求背后的商家问题。事实、商家原声和推断分开记录。

### WHAT：收益与预计目标

- 只描述产品能直接影响的收益，避免假大空或无直接因果关系的结果指标。
- 以终为始，写清上线后预计发生的可观察结果。
- 目标必须能衡量本方案是否有效；若因果链较长，补充直接指标、过程指标和护栏指标。
- 没有基线或可靠依据时，目标值保持 `待测量` 或 `待产品决策`。

### HOW：方案描述

#### 产品功能清单

用表格完整列出本次功能点，至少包含需求 ID、功能点、优先级、服务角色、对应问题和范围状态。

#### 系统改造描述

明确改造模块、改造点和 Before / After。按需覆盖：

- 后端：流程、数据结构、状态机、权限。
- 前端：流程、页面交互、组件复用。
- QA：用户用例、异常场景、跨系统交互。
- 设计：使用场景、信息结构、交互和视觉要求。

表达优先级为图 > 表 > 文字。只在结构确实需要时使用流程图、系统交互图、状态机或 ER 图；不能为了满足形式而虚构技术实现。技术细节未知时标记待研发确认。

#### 产品界面与交互

- 从商家使用视角还原场景，说明新增能力的价值与反馈。
- 明确商家角色和使用载体；原规范所称 `Bapp`、`API` 应按实际渠道确认，不得默认补齐。
- 覆盖入口、前置条件、操作、反馈、完成状态、异常与恢复。

## 商家端内审附加检查

- WHY：是否为真实商家问题，商家价值是否成立；若实际价值属于内部角色，是否如实标注。
- WHAT：目标是否是方案可直接影响、可观察和可衡量的结果。
- HOW：Before / After 是否清楚；系统、数据、页面和角色范围是否明确。
- 表达：功能清单是否完整且有优先级；图表是否服务于理解而非装饰。
- 交付：工程、QA、设计能否分别定位与自己相关的改造点、异常和验收。

## 与通用模板的映射

| 专项要求 | 通用模板落点 |
|---|---|
| 需求来源、为何现在 | 1.3 问题定义、1.4 证据 |
| 商家原声、替代解法 | 1.3、1.4 |
| 价值归属、影响面、周期、ROI | 2、4、10 |
| WHY / WHAT / HOW | 1 / 2 / 3—5 |
| 功能清单与优先级 | 4、5 |
| Before / After、改造范围 | 5；复杂内容可作为专项附件 |
| 商家场景、角色、Bapp/API | 1、3、5 |
| 内审检查点 | `PRD-QUALITY-CHECKLIST.md` + 本文件附加检查 |
